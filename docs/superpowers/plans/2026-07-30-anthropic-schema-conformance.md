# Anthropic Schema Conformance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every Anthropic Messages success, streaming usage, and error
body generated by Praxis AI conform to Anthropic's documented wire schemas.

**Architecture:** Add private Serde wire types shared by all Anthropic
emitters. Use those types for complete success and streaming usage objects,
then buffer and normalize only pre-stream upstream 4xx/5xx responses while
leaving successful SSE incremental.

**Tech Stack:** Rust 1.96+, Serde/serde_json, bytes, http, praxis-filter,
Praxis integration-test utilities.

## Global Constraints

- Rust stable 1.96+.
- Rust nightly is required for `rustfmt`.
- Praxis core remains unchanged. Published Praxis crates supply the dynamic
  response body mode and mutable response headers; `make patch-praxis` can
  optionally override them with a local `../praxis` checkout.
- Do not clone request, response, header, body, or SSE data unless correctness
  requires ownership.
- Do not buffer successful streaming responses; keep them in
  `BodyMode::Stream`.
- Locally generated errors use `request_id: null`; do not synthesize request
  IDs.
- Do not translate failures delivered inside an already-started HTTP 200 SSE
  stream.
- Preserve backend HTTP status codes when normalizing upstream 4xx/5xx
  responses.
- Keep generated example and filter documentation in sync; this change does
  not alter filter configuration, so `make lint` must confirm no generated
  documentation diff is required.

## File Structure

- Create `apis/src/anthropic/wire.rs`: private schema-complete Anthropic
  response, usage, delta-usage, and error wire types plus JSON/rejection
  constructors.
- Modify `apis/src/anthropic/mod.rs`: register the private `wire` module.
- Modify `apis/src/anthropic/messages_format/mod.rs`: build classifier
  rejections through the shared error constructor.
- Modify `apis/src/anthropic/validate/mod.rs`: build validation rejections
  through the shared error constructor.
- Modify `apis/src/anthropic/to_openai/mod.rs`: use shared request rejection,
  choose response buffering for successful non-streaming and all 4xx/5xx
  responses, normalize error bodies, and repair response headers.
- Modify `apis/src/anthropic/to_openai/response.rs`: serialize successful
  Messages responses through the shared types and translate upstream error
  bodies.
- Modify `apis/src/anthropic/stream_events/mod.rs`: use shared usage types for
  `message_start` and `message_delta`.
- Modify
  `tests/integration/tests/suite/examples/anthropic_messages.rs`: verify the
  example pipeline emits complete success and error schemas for streaming and
  non-streaming requests.

  fn should_transform_response(ctx: &HttpFilterContext<'_>) -> bool {
      let status = ctx.response_header.as_ref().map(|r| r.status);
      let is_error = status.is_some_and(|s| s.is_client_error() || s.is_server_error());
      let is_success = status.is_none_or(|s| s.is_success());
      let is_streaming = ctx
          .filter_metadata
