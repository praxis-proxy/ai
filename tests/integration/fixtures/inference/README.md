# Inference transformation fixtures

This directory contains versioned, two-sided fixtures for deterministic
inference transformation tests. Each scenario declares the client request and
observable expectations. Each `WireFixture` records both the client-facing
exchange and the transformed provider-facing exchange.

Normal CI replays the provider side locally. It does not need provider
credentials, an adjacent source checkout, a Python runner, or a network
service.

## Layout

```text
tests/integration/fixtures/inference/
  coverage.yaml
  scenarios/<protocol>/<case>.yaml
  recordings/<provider>/<protocol>/<case>.json
```

All documents use `version: 1`. Unknown fields, unsupported versions,
duplicate keys, invalid links, symlinks, and files outside the expected
extensions fail closed.

### Scenarios

An `InferenceScenario` declares:

- a stable slash-separated `id`;
- the client `protocol` and repository `example_config`;
- the `upstream_authority` replaced by the local runner;
- one or more coverage-manifest `features`; and
- ordered turns containing a client request and expected client/upstream
  response properties.

`${MODEL}` is substituted only when it is the complete value of a JSON string.
In later turns, an exact `${PREVIOUS_RESPONSE_ID}` JSON value is bound to the
immediately preceding client Responses resource ID so stored continuations can
be replayed without hard-coding generated identifiers.
SSE expectations use ordered named stages. Explicit repeatable stages consume
one or more contiguous frames; explicitly interleaved event names may occur
around the ordered stages. Unlisted, reordered, or ambiguous events fail.

### Wire fixtures

A `WireFixture` contains the scenario and protocol, truthful provider
provenance, normalization metadata, and ordered client/upstream exchanges. The
upstream request proves request transformation; the client response proves
response transformation; and the recorded upstream response drives offline
replay.

Normalization canonicalizes recognized exchange IDs and dynamic timestamps,
filters headers, removes provider padding, and preserves linked-ID
relationships. Model fields are not treated as exchange IDs.

### Coverage and provenance

Coverage statuses have these meanings:

- `covered`: replay has non-synthetic evidence from an allowed provider;
- `live_covered`: replay has a live recording from a declared provider;
- `synthetic_only`: controlled synthetic evidence exercises the behavior;
- `unsupported`: the manifest documents an unsupported behavior and reason;
- `provider_unsupported`: a named provider is unsupported with a reason while
  other evidence covers Praxis behavior.

Provider entries are requirements, not annotations. Every linked scenario
must have evidence matching its declared provider status. The checker rejects
unknown or one-sided links, duplicate scenario/provider recordings, unused
scopes, and coverage claims without the required evidence.

`provenance.kind` records origin:

- `live` is written only by `record-inference` after a provider exchange;
- `imported` is written by a normal `import-inference` run;
- `synthetic` requires `--provider synthetic --controlled-synthetic`.

Keep `provider`, `model`, and optional `source_id` source-truthful. Never relabel
an import as live or use controlled-synthetic provenance for imported provider
output.

## Recording a live fixture

The recording proxy listens on loopback, injects the selected credential only
into its outbound provider request, forwards responses incrementally with
bounded backpressure, and records normalized JSON or SSE.

For a local vLLM target:

```console
cargo xtask record-inference \
  --scenario messages/basic-nonstream \
  --provider vllm \
  --provider-base-url http://10.0.0.99:8000 \
  --model RedHatAI/Qwen3-Coder-Next-NVFP4 \
  --out /private/tmp/messages-basic-nonstream-vllm.json
```

Credential policy is provider-specific:

- `openai` reads `OPENAI_API_KEY` and defaults to `https://api.openai.com`;
- `anthropic` reads `ANTHROPIC_API_KEY`, defaults to the exact first-party
  `https://api.anthropic.com` origin, and sends `anthropic-version: 2023-06-01`;
- other provider slugs may read `INFERENCE_PROVIDER_API_KEY` for bearer
  authorization;
- vLLM needs no credential by default.

The command reads credentials internally; it never accepts them as CLI
arguments. A dedicated OpenAI or Anthropic credential is never sent to a
custom base URL. Credentialed provider calls can cost money and change
external state, so run them only with explicit authorization.

Omit `--out` to write beneath
`recordings/<provider>/<scenario-id>.json`. Default and explicit output modes
are no-clobber and reject an existing file or symlink.

## Importing request-hashed recordings

The importer accepts a strict external envelope containing `test_id`,
`request`, `response`, and optional `id_normalization_mapping`. Unknown fields
fail closed. The request `endpoint` is authoritative when a historical `url`
contains a duplicated API prefix. `test_id` becomes `source_id`; source type
names and normalization maps do not become fixture identity.

Exact `__type__`/`__data__` wrappers are recursively unwrapped. A
non-streaming response must become an object. A streaming response must become
a nonempty array of object chunks; each chunk becomes a data-only SSE frame in
order with a terminal marker.

The command runs the declared scenario through Praxis and verifies that the
normalized transformed upstream request exactly matches the imported request
before writing the two-sided fixture:

```console
cargo xtask import-inference \
  --recording /path/to/request-hashed-recording.json \
  --scenario messages/basic-nonstream \
  --provider openai \
  --out /private/tmp/messages-basic-nonstream-openai.json
```

Controlled synthetic behavior must be explicit:

```console
cargo xtask import-inference \
  --recording /path/to/controlled-429-envelope.json \
  --scenario messages/upstream-error \
  --provider synthetic \
  --controlled-synthetic \
  --out /private/tmp/messages-upstream-error-synthetic.json
```

An external recording may be at most 16 MiB. An optional JSON object of
literal replacements passed with `--redactions-file` may be at most 1 MiB.
Custom replacements cannot alter protected fixture identity or wire-structure
fields.

## Safety and review

The loaders enforce bounded document, body, SSE frame, nesting, node, and
decoded-string sizes before or during allocation. The implementation and its
tests are authoritative for exact limits.

Only the fixture header allowlist survives normalization. Credential headers,
cookies, hop-by-hop headers, `Host`, and local transport headers are removed.
The commit policy rejects credential-shaped text and absolute local user paths.
Private hostnames or content require explicit redaction and manual review.

Before staging a generated recording:

1. Confirm the command succeeded and wrote the intended new path.
2. Place the candidate beneath `recordings/` and update `coverage.yaml`.
3. Run the opaque checker before any diagnostic that could print fixture
   values.
4. Review both exchange sides, status, content type, SSE order, provider,
   model, provenance, source ID, normalization, and coverage links.
5. Confirm the artifact contains no credential, private user data, private
   hostname, local path, unstable padding, or infrastructure identifier.
6. Regenerate this README and run the replay tests.

Use these value-safe checks first:

```console
cargo xtask check-inference
cargo xtask sync-inference-readme --fix
rg -l -i 'bearer |authorization|api[_-]?key|/Users/|/home/|[A-Za-z]:\\' \
  tests/integration/fixtures/inference/recordings
```

The filename-only scan must produce no output. After it passes, run:

```console
make test-inference-fixtures
cargo xtask sync-inference-readme
git diff --check
```

`check-inference` validates the manifest/scenario/recording graph and the
default commit-safety policy without contacting a provider, starting Praxis,
reading credentials, or printing fixture bodies. The integration test then
starts only local replay infrastructure and compares the fully normalized
actual fixture with the committed fixture.

Do not diagnose a mismatch by dumping fixtures, response bodies, provider
headers, environment variables, or secret-bearing debug errors.
